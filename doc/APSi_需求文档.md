# APSi 传统需求规格说明书 (MVP 阶段)

## 1. 引言

### 1.1 目的
本文档旨在明确 AI-powered Procurement Intelligence (APSi) 平台 MVP 阶段的业务需求与功能规格。它为开发、测试和设计人员提供明确的构建依据，确保最终交付的系统满足目标用户的核心诉求。

### 1.2 项目背景
美国各州县政府的招标信息高度分散在数十个不同的门户网站中。目前，供应商（特别是中小企业）需要跨平台注册、检索招标信息，搜索效率极低。现有市场解决方案要么覆盖面窄，要么成本昂贵。APSi 项目致力于打造一个统一的招标信息检索平台，初期整合 50 个州及联邦政府（SAM.gov）的公开招标信息。

### 1.3 适用范围
本期 MVP 版本仅聚焦于“**招标信息聚合与检索**”。暂不涉及历史数据分析、价格竞争分析、以及利用 AI 对附件进行深度解析的功能。

---

## 2. 总体描述

### 2.1 产品视角
APSi 是一个基于 Web 的 SaaS 平台，主要由两部分构成：
1. **后端数据采集引擎**：持续从全美 50 个州门户和 SAM.gov 抓取最新的招标公告。
2. **前端用户工作台**：为供应商提供一站式搜索、过滤、查看和保存招标信息的用户界面。

### 2.2 用户特征
- **供应商/企业用户**：非技术背景，注重效率。希望通过简单的关键字和地区筛选，快速定位可投标的项目，并直接获取招标原文与附件。
- **系统管理员**：技术开发者，需要监控爬虫运行状态和系统健康度。

### 2.3 假设与约束
- **技术资源**：由单名全栈开发者完成 MVP 阶段的开发。
- **数据限制**：仅抓取公开门户网站，暂不触碰反爬虫机制严格的付费第三方平台。
- **分类策略**：先全量抓取，暂不预设细分产品类目（如不限食品行业）。

## 3. 具体功能需求

### 3.1 用户账户管理 (User Account Management)
- **FR-01 注册与登录**：用户可通过邮箱/密码进行注册、登录和登出。
- **FR-02 密码找回**：提供基于邮箱的密码重置功能。
- **FR-03 账户信息管理**：用户可查看基本信息和修改密码。

### 3.2 招标信息检索 (Bid Retrieval)
- **FR-04 统一搜索框**：支持对招标标题和描述进行全文模糊搜索。
- **FR-05 多维过滤器**：
  - 按**地区**过滤（支持单选或多选：全美、特定州如 CA, TX, NY）。
  - 按**发布时间**和**截止日期**区间过滤。
  - 按**发布机构类型**过滤（Federal, State）。
- **FR-06 列表展示与排序**：
  - 默认按“最新发布时间”降序排列。
  - 列表字段应包含：标题、来源州/机构、发布日期、截止日期、项目金额（若有）。
- **FR-07 翻页机制**：支持海量数据的分页浏览（每页 20/50 条）。

### 3.3 招标详情展示 (Bid Details)
- **FR-08 详情页概览**：展示招标的完整文本描述、原始发布网站、相关联系人信息。
- **FR-09 附件获取**：提供直接跳转至原始网站附件下载页面的链接，或直接提供附件下载地址（URL）。
- **FR-10 收藏与保存**：用户可将感兴趣的招标标记为“收藏”，以便后续跟进。

### 3.4 收藏夹管理 (Saved Bids)
- **FR-11 收藏列表**：展示用户已收藏的招标项目。
- **FR-12 移除收藏**：支持从收藏夹中移除不再关注的项目。

---

## 4. 非功能性需求

### 4.1 性能需求
- 页面加载时间不超过 2 秒。
- 全文检索响应时间（P95）不超过 1 秒。

### 4.2 数据时效性
- 联邦及各州公开门户的新增招标数据，延迟更新不超过 24 小时（每日增量抓取）。

### 4.3 安全性
- 用户密码使用强哈希（如 bcrypt）加密存储。
- 采用 HTTPS 协议保障数据传输安全。

---

## 5. 验收标准
1. **数据覆盖**：成功抓取并展示 SAM.gov 以及至少 80%（40+）的州级门户最新招标数据。
2. **检索体验**：用户能够通过关键字组合州代码，准确搜出目标招标公告，且页面无明显卡顿。
3. **完整流程**：用户可以顺利完成“注册 -> 登录 -> 搜索 -> 查看详情 -> 点击附件链接”的核心使用路径。
